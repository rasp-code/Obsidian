# Quick Review
**Planning**
- scrum: 
	- **the idea**: *A framework built on **fixed-length iterations (sprints)** with defined roles and ceremonies, delivering a usable increment at the end of each sprint.*
	- **keywords**: ***sprints*** (1-4 weeks), PO / Scrum Master / Developers, Product Backlog, Sprint Backlog, increment, DoD (Definition of Done), sprint planning, daily stand-up, sprint review, retrospective, refinement, user story, story points, velocity, burndown chart
- kanban:
	- **the idea**: *A **continuous-flow** system where work is visualized on a board and WIP is limited so that tasks get finished rather than too many being started.*
	- **keywords**: continuous flow, board, columns, ***WIP limit***, bottleneck, lead time, cycle time, throughput, no roles, no sprints, continuous improvement
- hybride:
	- **the idea**: ***A lightweight Scrum** that keeps the sprint cadence and backlog, **borrows Kanban’s board and flexibility**, and adapts to the team’s context.*
	- **keywords**: 2-week sprints, daily, Jira board, backlog prioritized by the PO, sometimes WIP limits, lightweight estimation, urgent bugs mid-sprint, tailored ceremonies, pragmatism

**Cloud**
- **Concept**
    - on-demand resources
    - pay-as-you-go
    - vs **on-premise**
    - elasticity
    - vendor lock-in
    - cost monitoring
    - data sovereignty
- **Service models**
    - IaaS: VMs, network, storage (EC2)
    - PaaS: deploy your code (Heroku, App Service)
    - SaaS: ready-to-use software (Gmail, Slack)
    - FaaS / Serverless: functions, billed per execution (Lambda)
- **Deployment models**
    - public
    - private
    - hybrid
    - multi-cloud
- **Providers**
    - **AWS**: historical leader, widest catalog, market reference
    - **Azure**: integrated with the Microsoft ecosystem (Entra ID/Active Directory, .NET, Microsoft 365), very present in large companies
    - **GCP**: strong in data/analytics (BigQuery), AI/ML and Kubernetes (created by Google), smaller market share
    - **OVHcloud**: French, low prices, data sovereignty and GDPR
    - **Scaleway**: French, developer and startup oriented, simple offering, data sovereignty

**NoSQL**
- **Concept**
    - “Not Only SQL” : non relationnel
    - schéma flexible (schemaless)
    - scalabilité horizontale native
    - haute performance sur cas d’usage précis
- **SQL vs NoSQL**
    - schéma : fixe vs flexible
    - relations : jointures vs dénormalisation
    - scalabilité : verticale vs horizontale
    - transactions : ACID complètes vs variables
    - critères de choix
        - NoSQL : gros volumes, schéma changeant, accès par clé, faible latence
        - SQL : relations complexes, transactions fiables, requêtes ad hoc, intégrité
    - en pratique : on combine (SQL + Redis + MongoDB)
- **Familles**
    - **Document** :
	    - JSON/BSON, schéma flexible
        - e.g. MongoDB, Firestore, Cosmos DB
    - **Clé-valeur** :
        - e.g. Redis, DynamoDB
        - cas d’usage : cache, sessions, compteurs, panier
    - **Colonnes larges**
	    - écritures massive
	    - e.g. Cassandra, Hbase
    - **Graphe**
	    - noeuds + relations
	    - e.g. Neo4j
- **Modélisation**
    - modéliser selon les requêtes (query-driven) et pas ? comme en SQL
    - dénormalisation : duplication ou imbrication
    - embedding vs referencing (MongoDB)
- **Distribution**
    - **Sharding** : découpage des données sur plusieurs machines
        - shard key
    - **Réplication** : copies pour haute disponibilité
- **Cohérence**
    - ACID : Atomicité, Cohérence, Isolation, Durabilité
    - BASE : Basically Available, Soft state, Eventually consistent
    - Eventual consistency
    - Théorème CAP : Consistency, Availability, Partition tolerance
        - en cas de partition : choix C ou A
        - AP vs CP
        - exemples : Cassandra (AP), MongoDB (CP par défaut)
- **Redis (cache)**
    - in-memory, très faible latence
    - structures : string, hash, list, set, sorted set
    - cas d’usage : cache, sessions, rate limiting, files
    - TTL / expiration
- **MongoDB (document)**
    - collections, documents, `_id`
    - CRUD : insertOne, find, updateOne, deleteOne
    - opérateurs : `$set`, `$inc`, `$gt`, `$in`
